# 自分で仕事の仕組みを作り、土地を広げるゲームへ

更新日：2026-10-22 JST。独立したAIプランナー／革命家の観点による設計レビュー。
作者本人による監修済み・実児童による評価済みという意味ではない。

## 現状の判断

いま遊べるのは、木石の手採集、手運び、仲間の配置、入庫、自衛をまとめた短い試作。
旧回収方式の実入力QAでは約21〜26分で9回の防衛を完走した。これは高速入力と保存の
引継ぎを含む記録で、一般プレイヤーの標準時間ではない。数時間のゲームが完成したとは
言えない。新しい手動レールの敷設が入った後の通し時間も未計測である。

現行の主な意思決定は、木石で採集役を増やすか弓兵を増やすか、兵を上下どちらへ置くか。
道具は作業間隔を2段階縮め、レールは4採集点を同じ家へ接続する。これだけでは、9回を
30回に増やしても、すでに知っている解をより長く実行する遊びになる。

今回の手動敷設は必須の修正である。しかし、手で線を引けるだけで自動化ゲームが完成する
わけではない。経路が運搬の速さや設備の置き方へ影響し、次に接続したい目的地が必要。

## 中心に置く体験

> 自分で苦労した仕事を、自分で設計した仕組みに任せる。
> 空いた手と生産力で、まだ行けなかった土地を開く。

採集 → 小屋へドラッグ → 採集役を置く → 自分で線路を敷く → 自動で届くのを確かめる →
加工設備を置く → 入出力をつなぐ → どの土地を開くか選ぶ → 新しい仕事を組み立てる。

防衛は、この拠点の仕事が成り立つかを試す節目にする。いつでも襲撃を起こして採集を
中断する構造にはせず、プレイヤーが準備を終えたら市の依頼／出荷を始める。
主人公HP、味方の勝手な移動、常時揺れる画面は戻さない。

## まず完成させる手動レール

以下は今回の実装を評価する条件。後述の加工・土地拡張は別の未実装計画である。

1. プレイヤーが採集場所を選ぶ。ゲームが勝手に次の採集点を選んで線路を完成させない。
2. 地面を順に選んで、自分で曲がり角を決める。最短経路の自動生成はしない。
3. 置ける位置・次に伸ばせる位置・接続していない端が、線と色で見える。
4. 接続前の仮置きでは入庫しない。キャンセルでき、必要費用は確定前に分かる。
5. 運搬車は実際に敷いた線を通る。長い経路なら届くまでの時間も長くなる。
6. 止まる理由は文字だけでなく見た目で分かる。未接続端は点灯し、素材がある採集場は
   荷が待ち、届いた小屋には入庫の反応がある。
7. 外す・敷き直す操作がある。敷設ミスで永久に資金を失って詰まらない。
8. 画面を指で触っても線路を置け、資材のドラッグ納品や仲間の移設と競合しない。
9. 保存して再開しても手描きの曲がり角を維持し、荷が直線へ瞬間移動しない。

### 経路の形を、実際の仕事へ結び付ける

以前の配送は2秒ごとに新しい荷を出す方式だった。貨車の数が無限なら、長い経路でも
一度流れ始めた後の輸送量は変わらない。曲がった線を走る見た目と初回の到着遅延だけでは、
経路を直す理由が弱い。その指摘を受け、現在は同じ採集点の荷が運送中なら次便を出さず、経路の長さが継続した輸送量にも効くようにした。空車の帰路・分岐・渋滞は未実装で、物流全体の最適化まで完成とは扱わない。

次の加工設備と合わせる際は、路線ごとに貨車を1台持ち、往復して荷を積む方式を最初の候補に
する。すると、近くへ加工場を置くか、貨車の容量を増やすか、路線を追加するかが仕事量に
影響する。ただし既存の生産・兵費用へ大きく影響するため、今回の手動敷設修正へ無検証で
混ぜない。往復を入れた固定版で新規から再び採集・防衛・最後まで通す必要がある。

初回はシンプルな1本の経路でよい。分岐・合流・優先配送・路線別信号を最初から全部
入れない。1本の手動経路で「選んだ形を車が走る」が伝わってから分岐を追加する。

## 連打の扱い

採集効率を指の速さで決める設計は主軸から外す。数時間を考えるなら、速くクリック
するほど得という状態が続くと、建設を考えるより指を使うほうが最善になる。

- クリック1回の斧／ピッケルの手応えは残す。
- 押し続ける操作でも、一定のテンポで採れるようにする。早押しでも一定以上には加速しない。
- Spaceは選択した対象を手伝う任意の入力。Spaceを押さなくても初回採集・納品・建設まで進める。
- 手で助ける利益は序盤に分かりやすく、採集役や設備が増えたら相対的に小さくなる。
- 採集が自動化した後は、入力の速さではなく「どこへ何を運ぶか」に時間を使う。
- 既存の連打測定は独立した入口に残せる。測定の記録や倍率を拠点の物流へ持ち込まない。

ホールド採集を入れた後は、クリック数より採った量・手運び回数・初回自動入庫までの操作を
見る。「クリックが少ないからつまらない」とは判定しない。

## 次の一周で必要な生産の段階

木石の単純な数量増加と別の仕事を、1つずつ増やす。各段階に、初回の完成と次の目標が必要。

| 段階 | 手作業／判断 | 自分で作る仕組み | 目に見える報酬 |
| --- | --- | --- | --- |
| 森の小屋 | 木石を採って運ぶ。採集役をどちらへ置くか | 採集点から家への手動路線 | 地面の荷が家へ届き、手運びが要らなくなる |
| 製材所 | 木を在庫にするか、板へ加工するか | 製材所を配置し、木を入れ、板を家へ運ぶ | 丸太が板になって出てくる。橋の工事が進む |
| 石の工房 | 石を兵に使うか、切石へ加工するか | 石の入力と切石の出力を接続する | 家／橋が完成形へ変わり、新しい土地が開く |
| 川向こう | 森と採石地のどちらを先に開くか | 新しい採集地と旧拠点を自分で接続する | 画面が縦へ広がり、新しい景色と働く仲間が増える |
| 市の大口依頼 | 指定の品を揃えるか、拠点増産へ回すか | 配送を見直し、依頼を満たす仕事を組む | 市の報酬、新設備、完成した拠点の記念画面 |

最初の加工設備は製材所1種類に絞る。木2→板1のような少ない品目から始め、複雑な
レシピ表を先に見せない。未加工木が不足したら材料の絵が空になり、出力先がなければ
板が設備のそばに積もる。未納品の板を一時的に手で小屋へ運ぶ救済も残す。

採集地を開く条件は、生産量の累計だけにしない。「板を実際に橋の工事場へ運び入れた」
ことで工事が進む。建設場所と完成形が同じ画面上にあり、数値のボタンだけで土地が増えない。

### 最初の加工工程の調整案（未実装・実プレイで検証する値）

- 製材所：プレイヤーが地面に置く。木2を5秒で板1にする。最初は1台のみ。
- 製材所の前に木の荷があること、出力に板があることを別々に描く。
- 家への木納品と製材所への木供給は選択できる。初回は別々の採集点を担当させ、
  分配器や信号を学ぶ前に「どちらへつなぐか」を成立させる。
- 小橋：板12＋石20を工事場へ届ける。単に待つのではなく、輸送先を自分で変えて完成させる。
- 完成先には木地と石地の選択を見せる。1つを選んでも他方を永久に失わない。

これらの数字で何分になるかはまだ測っていない。採集量・建設費を倍にしてプレイ時間を
伸ばす調整は行わず、手運びと自動生産の両方で最初から試して決める。

## どれくらい遊べるようにするか

現時点の公表可能な事実は「旧版のQA記録で一周約21〜26分」のみ。まずは上記の
製材と1回の土地拡張を加えた一周で、60〜120分を目標候補にする。ただし、これは
提供済みの遊べる時間でも、保証値でもない。初見で何をしているか理解でき、途中で
次の仕組みを作りたくなる一周を実際に測ってから、公開時の表現を決める。

何時間も遊べる版を目指す場合は、さらに別の制約を持つ土地が必要になる。
川の向こうで生産量だけを3倍にしても拡張性とは呼ばない。例えば次のように、既存の
設備を別の使い方で組み直す場を増やす。

- 森：短い回収路を作って最初の手作業を任せる。
- 採石地：離れた原料を運び、加工場を原料側へ置くか家側へ置くかを考える。
- 川：限られた渡河箇所に複数の荷が集中するため、路線をまとめるか分けるかを考える。

この順序なら、建設の知識と育てた仲間が次の土地で役に立つ。魂の倍率を上げて初期化
する仕組みや、同じ防衛を延々と増やす仕組みで時間を稼ぐ必要はない。

## iframe・縦スクロールを使う画面

現行は戦場を約49〜55vhへ押し込み、残りにカードを詰めている。HUDが敵を隠れたり、
狭い場所に複数の工房ボタンが並ぶ原因にもなっている。

次の土地拡張では、最初に全景を極端に縮めて収めない。元の小屋から上下へ土地を増やし、
プレイヤーが自分で縦へ見に行く画面にする。勝手なカメラ移動と揺れは入れない。

- 上：小屋・手元資材・今の1つの目標。ゲームの状況を短くまとめる。
- 中：土地と生産設備。広げた土地は縦へ続き、建設と納品を直接行う。
- 下：仲間・設備の一覧、図鑑、設定。画面内の小さいリストをさらにスクロールする構造は減らす。
- 自動入庫の通知は小さく。画面外の土地に更新があっても、視点を勝手に戻さない。
- 座標はワールド座標に統一し、ページをスクロールした後もレール・資材・兵の判定を揃える。
- スマホでは建設モードの地面と、ページをスクロールできる余白／操作を明確に分ける。

外部ブログのiframe高さをゲーム側だけで無制限に増やせるとは仮定しない。固定高さの埋込、
高さを調整した埋込、全画面の3条件でスクロール・ドラッグ・ボタン到達を確認する。
自動高さ調整にpostMessageを使う場合は、親記事側の受信処理が必要である。

## 素材の妥協を防ぐ確認ルール

石ほりはピッケルの柄・左右へ突き出た金属部・岩へ下ろす軌跡が、カードの小さい絵でも
分かること。木こりと同じ斧の姿を流用しない。静止画を直すだけでは採掘の役割は伝わらない。

- 待機、振りかぶり、岩へ当たる、戻りの4姿勢を同じ人物・装備・大きさで揃える。
- 岩へ当たった瞬間に石の小片と採掘音、少し遅れて地面の石、という因果を揃える。
- 顔の細部より、道具と動作を優先する。キャラ名を隠して木こり／石ほりを判別できるか見る。
- 素材シートの端切れ、セルごとの足元と身長、実ゲームの64px表示を同時に確認する。
- プロフィールやカードの絵も同じ素材へ更新し、画面ごとに別人にならないようにする。

## バブルガムの8つの面白さへの対応

| 軸 | このゲームの主な担当 | 合格を判断する具体的な出来事 |
| --- | --- | --- |
| 動かす気持ちよさ | 道具、素材ドラッグ、線路の敷設 | 道具が岩へ当たり、落ちた石を運び、自分の線を車が走る |
| 上達 | 運ぶ量と距離の改善 | 同じ採集役でも、配置／経路を直すと手待ちが減る |
| 判断と駆け引き | 加工先、建設位置、次の土地 | 木を兵に使うか、板と橋へ回すかを選んで結果が変わる |
| 成長と報酬 | 仲間、生産、建設完了 | 以前の手運びが不要になり、橋の先へ仕事場が広がる |
| 集める | 仲間／設備の見た目 | 新しい役割を得て、一覧と土地上の両方で増えたと分かる |
| 探索 | 土地拡張 | 次の地形を見て、別の経路を考え始める |
| 物語となりきり | 小屋から市へつなぐ営み | 依頼の品を自分の拠点で揃え、道が実際に開通する |
| 人と遊ぶ | 今回の必須項目にしない | 将来の拠点共有は、他の軸が成立してから判断する |

小さく即座に返る報酬は、道具が当たる音、納品、路線を1区間置く反応。苦労の後に
残る報酬は、「最初は手で運んでいた仕事が、自分が敷いた路線だけで動く」と気付く瞬間。
後者を作らずにボタン購入音と数値増加を増やしても、作者の求める面白さには届かない。

## 開発順と受入条件

1. ピッケルと手動線路。1本を自分で敷き、車が選んだ角を曲がり、届く。取消／保存も成立。
2. 任意のホールド採集と、連打必須の説明を除く。Spaceなしの新規プレイで同じ基礎を作れる。
3. 製材所1種類。自分で置いた入力と出力が動き、木のまま使うか加工するかを選べる。
4. 小橋と1区画の拡張。工事場へ実際に品物を届けると、新しい採集地が使える。
5. その1区画で全編の再レビュー。理解・停滞・自動化の喜びを見てから次の土地を足す。

レビューでは『最後まで操作できた』だけで合格にしない。毎回、①どの仕事を自分で
組み立てたか、②その結果何が楽になったか、③次に何を作りたくなったか、を画面と
実入力の記録から説明できるかを見る。実験用に資源や設備を与えた確認と、新規から
正規資材で進めた通しプレイは区別する。

## 実装上の分割

- `rail-core.js`：手で決めた点列、接続、費用、荷の経路位置。描画・DOMから独立。
- `outpost-camp.js`：敷設操作、キャンセル、路線表示、家への受取。自動で道を作らない。
- 将来の生産定義：設備の入出力と所要時間をデータ化。描画／シミュレーションと分ける。
- 将来の土地定義：採集点・通路・工事場・解禁条件を区画ごとに持つ。既存の固定4点を
  単純に大量複製して、画面上へ重ねない。
- セーブ：設備、路線、区画を安定したIDで参照し、追加時に既存経路や資材を失わない。

今回は未接続の拡張用モジュールだけを先に追加しない。製材・土地の実装を行う段階で、
実画面の動線と合わせて純粋モデルと保存形式を決める。


## 個別運搬と資材スキル（今回実装）

地面の物は初期から木1個・石1個ずつの独立した物体。個数32の束に自動集約しない。
基礎の手荷物容量は1。資材で持ち運び1→2→4、採集間隔1→0.8→0.6秒、荷車速度
1→1.25→1.5倍の3枝を選べる。上位には同じ枝の前提があり、費用は実納品した木石から引く。
容量を増やしても、ドラッグ中に追加の品物を実際になぞって持ち物へ入れる。
地面の品物を勝手にまとめて回収する機能ではない。レールも経由点を自分で置いて確定する。

これにより『自分で採る・1個ずつ運ぶ』→『どの手仕事を楽にするか選ぶ』→
『自分で組んだ設備へ仕事を渡す』を最初の成長にする。面倒を増やすだけでは面白くない。
何が改善されるかが事前に分かり、実際に改善した状態を眺められることを評価する。
