# Mythos Slayers II 領地・城攻略の設計

2026-11-17。Astra設計、Sol実装、Rootアート・試遊・公開。main `c4759f8` の編集ソースを継続する。正式リリースでも全リセットでもなく、preview版の次の制作。元ゲームは変更しない。

## 今回完成させる一巡

拠点で採集・納品して部隊を増やす → 攻略地図で城と前哨を選ぶ → 地図上の経路を通って遠征先へ切り替わる → 左の進軍口から軍勢が展開する → 守備隊を倒し城門を攻撃する → 制圧地で資源を採り、実物を集める → 荷車へ手で積む → 拠点へ輸送し、実物を荷下ろしする → 拠点の搬送設備で倉庫へ納める。

城、歩行、地図移動、制圧地の供給が、見た目だけでなく実際の状態変化に結びつくことを完成条件とする。移動時間だけ延ばした旧画面、城の絵だけ追加した旧全滅勝利、領地名だけ付けた資材自動加算では完了としない。

## 実装の分界

拠点の `S.factory` と `S.camp` は常にそのまま維持し、既存の生産と物理搬送を通常のtickで進める。表示だけ `home / battlefield / territory` に切り替える。どの表示も1600×900の平地、既存カメラ・兵士描画を使う。

遠征先の生産は `S.territories` の独立した nodes / drops / stockpile / cargo に保存する。既存SupplyCore・資材定義・物理ヘルパーを可能な範囲で再利用し、専用の小さな採集・ドラッグ・集積処理を加える。**S.factoryとS.campを別領地のデータへすげ替えない。** 現行のstateRef切替は作業中ジョブや保持中資材に副作用があり、倉庫座標も固定されている。

拠点の全ガジェットは従来どおり使える。遠征先で全ガジェットを複製した第2工場を作ること、多領地の自律輸送網、非表示の全領地を同時に物理シミュレーションすることは今回の実装範囲に含めない。領地では手採集・集積・荷車と、可能なら1隊の生産員手動派遣までを完成させる。親に派遣が実装範囲外となる場合を報告し、UI上で派遣できるように見せない。

## 攻略地図とMAP移動

- 拠点の上部は現在の45px程度の1行を維持し、「攻略地図」を主入口にする。クリックで地図画面を開く。地面の巨大な常設パネルは追加しない。
- 地図には拠点と10地域、地域内の前哨2つ・城1つを描く。未解放、攻略可能、制圧済みを形と色で分ける。城アイコンは単なる丸印でなくRootの城アートの縮小、前哨は小さな砦・旗で区別する。
- 未制圧地を選ぶと敵種・人数・攻略ヒント・出陣人数・確保できる資源を短く表示。「ここへ出陣」を押すまで開始しない。制圧済みなら「領地へ移動」で再訪できる。過去地域を選ぶ手段を残す。
- 出陣確定後、地図上の拠点から選択地まで経路を約0.8〜1.2秒で進む部隊印を表示し、選択した名前を出して戦場へ切り替える。この経路中に守備隊の攻撃や戦闘時間を進めない。移動演出は勝敗判定を兼ねない。
- 戦場・領地からも「拠点へ」と「地図」を見つけられる。戦闘中の「拠点を見る」は視点移動だけで、撤退とは別操作。見ていない戦闘と拠点の生産も進行する。既存の小屋や地図が一時停止するルールは維持し、地図で眺めている時間を戦闘へ加算しない。
- 侵攻開始を戻る/閉じる/画面再読込で二重実行しない。地図移動は保存可能な遷移にし、再読込時には開始済みの戦場を1つだけ復元する。

## 専用戦場と軍勢の展開

拠点の小屋・資源ノード・生産員・道具を戦場へ重ねない。ホームの生産は裏で継続するが、見えていない木や設備の当たり判定で兵を止めない。表示しない拠点の資材を戦場クリックで採集できる実装にもさせない。背景、入力、描画対象、軍隊の衝突対象を同じsceneで選ぶ。

戦場の初期案は進軍口 `(90,450)`、前衛の最初の接敵帯 `x=850〜1000`、城門 `(1370,450)`。上下の通路は `y=330/570`。城は足元がこの座標に接地するように描き、城門の目標判定を絵と一致させる。前哨は同じ城アートを小さくし、頭領の城は大きくする。章別の地形エンジンは追加しない。

- 出陣時の拠点配置は帰還用に保存し、戦場での座標と分ける。ホームの軍隊配置を戦場の左入口座標で上書きしない。
- 戦闘員は入口から少数列で入る。剣士が前、弓兵が後ろ、バリスタが後方。部隊内は3〜5列、兵同士の間隔22〜28px程度を確保し、全員が重なった1つの塊にならないようにする。手動配置の上下関係は隊列の上下順に反映する。
- 速度を極端に落とさず、約8〜12秒で先頭が接敵する距離にする。大部隊は先頭から最後尾まで最大3秒程度の差で展開する。実際に所有している人数だけ描き、物量感のために無料の兵を増やさない。
- 出陣直後は入口から城までを一度見せ、その後は部隊が視認できる倍率へ寄せる。手動パン/ズーム後は常時追従しない。「部隊を見る」で追い直せる。横持ちで全景にすると兵が豆粒になる場合は部隊を優先する。
- 歩行中は足または歩行フレームが交互に動き、移動方向へ向く。静止中は歩行を止める。スプライトシートに歩行がない兵は足元の交互運動・小さな上下動・上体の傾きなどを使って前進を読めるようにする。全身の激しい左右振動を歩行の代わりにしない。バリスタは足踏みではなく車輪/車体の移動として見せる。
- 左入口からの進軍、戦闘での追撃、撤退でも同じ移動状態を使う。表示だけ歩かせて当たり判定座標を固定しない。動きを抑える設定では跳ねを減らし、移動と向きは残す。

## 守備隊・城門・勝利

既存30遭遇・10ボス・盾/飛行/分裂/装甲/潜伏/祈祷・味方HPを再利用する。前哨2つを順不同で制圧し、両方の後で城、城の後で次地域という進行は維持する。

守備隊の一部は城前、残りは城門から2〜3群で出る。接敵してから既存の増援時計を始め、通常は全投入20〜35秒以内。後半は既存の20〜30体以上が画面で複数同時に戦い、群れに対して前衛と射手が働く。最初の3体/弓1人は通常獲得の入門として維持し、その後の増員が見た目と戦力の両方を大きくする。

城門は独立した耐久を持つ。初期案は前哨15、地域の城40、最後の城60。敵HPの一律増加はしない。守備隊と子敵が全滅すると、残った味方が城門へ歩いて攻撃する。既存の攻撃間隔と攻撃力で耐久を減らし、0で旗が敵色から味方色に変わる。城門攻略は数秒程度を目安とし、兵が強ければすぐ落ちてよい。最低待ち時間は設けない。

城を攻撃する位置は城の足元前方。画像の屋根や透明余白を当たり判定にしない。城を破壊可能にしたことを独立した「城門」耐久表示と攻撃反応で示す。守備隊が全滅しただけでは制圧フラグ・金貨・領地解放を確定しない。

撤退/全滅では城耐久と守備隊進捗を戻して再挑戦。味方人数・訓練・研究・設備は残る。v18の帰還と同様に体力は帰還で全快。新しい敗戦課金や回復待ちは追加しない。

## 制圧地の小作業場

城門制圧で領地データを一度だけ作る。兵は帰還へ向かい、結果に「領地を使う」と「拠点へ」を出す。領地は地図から何度でも再訪できる。再訪で資材が初期状態へ戻ったり、採集済みノードが無償再生成されたりしない。

領地の平地には味方旗になった城、資源ノード、資材集積枠、荷車を配置する。資源の配置案は入口近くから順に木 `(500,430)`、石 `(720,560)`、鉱石 `(940,420)`、集積場 `(300,560)`、荷車 `(190,560)`。一領地に全部並べる必要はなく、その陣地の主資源1種＋城なら2種程度に絞る。資源量・位置は保存する。

- 北前哨は木、南前哨は石を基本とし、後半に麦・鉱石の領地を混ぜる。城は鉱石を持つ供給拠点として価値を加える。最初の城に鉱石を見せても、採掘には既存研究が必要。初期の手採集条件と研究コストを勝手に解除しない。
- 攻略前の地図には資源の種類と初期可採量を表示する。初期案は前哨の木120個または石80個、城の鉱石40個（未研究なら研究条件つき）。再訪では初期量ではなく保存された残量と集積/積載分を区別して表示する。現地の残量表示と一致させ、入るたびに初期量へ戻さない。
- ノードを押すと既存資材定義の作業量で採れ、地面に個別の木/石/鉱石が落ちる。採集ボタンで倉庫の数字が増える方式にしない。
- 制圧する供給上の利点として、領地のノードは「豊かな採取場」とし、通常と同じ作業1回の完了で実物2個を出す。初期なら木は3打で2個、石は5打で2個、鉄は12打で2個。既存研究のmanualPower/manualIntervalを尊重し、高い採集力では完了回数×2個。派遣員も通常1回の採集完了で2個を出す。残量と地上の空き分で制限し、実際に出せた個数だけ残量を減らす。残り1個または空き1個なら1個、空き0なら採集を止める。出せなかった分を後から無償で発生させない。地図には「豊かな林・採集量2倍・残量120」の短文で予告し、現地の2個落下で効果を見せる。既存の拠点ノードは変更しない。
- 落ちた資材はドラッグして置き直せる。集積枠へ運んだ分だけ保存され、個数と絵で見える。集積場は倉庫への納品場所ではなく、その領地に置いておく物資置場。未搬入品を数字へまとめて自動回収しない。
- 集積枠は個別itemのリストを保持する。外へ取り出す時は実物を地面へ戻す。数量だけを消費して無関係な新資材を生成する手続きにしない。
- 木・石の再生は既存ルールと同等にし、木は採集量が多く軽い、石は重い、鉱石は採掘研究と長めの採集作業が必要という違いを残す。訪問していない領地の資材を時間経過で無料追加しない。
- 領地の地面上限は既存研究による上限を参照する。満杯なら採集を止める。資材を消す、勝手に集積する、無料納品する対処は禁止。

生産員派遣を入れる場合、現在の既存隊から1隊を選び「この領地へ派遣」、現地のノード近くを押して配置する。二重所有や無料複製はせず、その隊は拠点での作業を止める。現地で採集した実物だけ落とす。遠方の全領地を同時処理せず、訪問中の領地のみ稼働でよいが、その条件を明記する。「拠点へ戻す」で元の配置へ戻せる。派遣状態・元座標・現地座標を保存し、地図切替で配置が消えないようにする。派遣と戦闘は混ぜず、作業員を戦闘ダメージの対象にしない。

## 手動の積載・輸送・荷下ろし

荷車の初期容量は個別資材12個程度。木も石も同じ個数枠を使い、質量は地面の搬送時に効く。容量研究や燃料課金は今回は増やさない。

1. 地面または集積場の実物を荷車へドラッグして積む。集積は任意で、地面からの直積みを可能にする。手持ち数は `HarvestSkillCore.effects(S.harvestSkills).carryCapacity` の既存研究（1/2/4/6/8/12/16個）を尊重し、近くの実物をその上限までまとめて運べるようにする。積んだitemは元の領地リストから移し、荷台へ表示する。積載数と木/石/鉱石の内訳を見せる。荷車の空き分だけ積み、残りは元へ残して知らせる。領地だけ常に1個ずつに戻さない。
2. 「この荷物を拠点へ運ぶ」を押す。空荷なら通常の「拠点へ戻る」。押す前に実際の積載内容が見える。資源ノードの残量や集積場の全在庫を勝手に積み込まない。
3. 地図上を荷車印が拠点へ進み、約1秒後に拠点の荷下ろし場へ到着する。長い待ち時間を経済制限に使わない。
4. 荷車は小屋から離れた空き地に残る。表示案は `(230,500)` 前後、既存の資源や設備に重なる場合は空き地へずらす。倉庫受領範囲から十分外し、少なくとも実際の受領半径＋80pxを確保する。「荷下ろし」で積んだitemをそこへ個別に置く。ここで `factory.inventory` は増やさない。既存の受領範囲や搬送装置の入口と重なった結果、同じフレームで全量納品される既定位置を選ばない。プレイヤーが後から自分で搬送装置をつないだ場合は通常の設備効果として扱う。
5. プレイヤーが手で運ぶか、既存の送風機/箒/コンベア/積み込み機等で小屋の納品口へ送る。実際の納品で初めて資材所持数が増える。

拠点の地面上限に空きがない場合、積荷は荷車に保持する。空き分だけ荷下ろしし、残りを削除しない。「地面がいっぱい・荷車に残り○個」と表示して、まず既存資材を運べるようにする。未荷下ろし品がある間に次の輸送を始める場合は、荷車の空き容量で制限するか、先に荷下ろしする理由を表示する。無制限に貨物を貯める隠し倉庫にはしない。

輸送中の資材は所属を1つだけ持つ。領地の地面、集積、荷車、輸送中、拠点荷車、拠点の地面のどれか。出発時にmanifestを保存し、到着・荷下ろしは輸送IDごとに一度だけ適用する。再読込で元領地と拠点の両方へ資材が現れない。拠点drop.keyは通常のnext採番を使い、領地のkey衝突を持ち込まない。

## 小さい画面の導線

常時表示は1行。拠点は「攻略地図」、戦場は「進軍/交戦/城門耐久・部隊を見る・撤退」、領地は「領地名・集積数・荷車○/12・拠点へ」。必要なら2行にしてよいが横持ちで盤面を大きく覆わない。

敵情報、派遣員の選択、積載内訳はユーザーが開いた時だけ表示する。開いた説明を閉じる手段を固定する。旧侵攻版の大型floating overlayへ戻さない。

初勝利の案内は「確保した林で採る → 荷車へ積む → 拠点へ運ぶ → 荷下ろし → 倉庫へ納品」の実操作を順に追う。最初から説明文を全部表示しない。荷物を自動で積んでチュートリアル完了にしない。

戦場でホーム用の採集/ガジェットボタンを押しても、見えていない拠点に設置しない。戦場では必要な戦闘操作と「拠点を見る」に切り替える。領地で未対応のガジェットは「拠点で使用」を明示し、動くふりをしない。拠点へ戻ると元の道具選択・手動配置が復元できる。

## 保存と移行

v18の進軍・交戦・帰還中セーブは、その戦闘をv18の同一平地ルールで完了させる。ロード時に左入口へ飛ばす、城門を途中追加する、敵の状態を作り直すことはしない。通常帰還してidleになってから新しい地図/戦場方式へ移行する。

既存の30陣地制圧集合、連続クリア値、研究、人数、訓練、金貨、初回報酬、拠点ノード・地上資材・設備をそのまま保つ。v18で制圧報酬として追加したノードを消したり別座標へ移したりしない。

既制圧地には再訪時に一度だけ領地データを生成してよい。ただし金貨・初回クリア報酬を再支給しない。新方式の制圧による新規供給先は領地に作り、拠点に同じ新資源ノードを二重生成しない。既存ノードが残る旧セーブと、新規セーブで領地を使う差は仕様として許容する。

新状態はscene、表示中領地、地図移動、領地別ノード/実物/集積、荷車、輸送manifest、派遣情報、戦場の部隊入口座標/城門耐久を保存する。旧v18判定には明示した戦闘バージョンを使い、グローバル版名だけで進行中のルールを切り替えない。

SaveGuardの別タブ更新防止を維持する。採集地・輸送・sceneを保存/書出しの正規化から落とさない。slot=new-gameをリセットしない。生セーブ・IDはrepoへ含めない。

## 検証と最小完成条件

- 通常獲得の最初の部隊で、地図表示→経路演出→専用戦場→歩行→守備隊撃破→城門への実攻撃→制圧まで確認する。
- 大部隊の代表例で入口の列、歩行の違い、複数敵との同時交戦、城攻略を視認する。所有数以上の飾り兵は出さない。
- 戦場表示中も拠点木こりと物理搬送が続き、隠れたホーム資源を誤ってクリック/設置しないことを確認する。
- 制圧地で実際に木を採り、集積場へ移し、荷車へ積み、輸送する。拠点で荷下ろししても所持数が増えず、倉庫への物理搬送で増えることを確認する。
- 領地に置いた未輸送資材・荷車積載・派遣配置が再訪と再読込で残る。
- 地図移動中、進軍中、城門攻撃中、領地採集中、輸送中、拠点未荷下ろしを保存し、再読込による報酬/資材の増殖がないことを確認する。
- 旧v18 activeを完了してから移行し、旧制圧ノードと仲間配置が保持されることを確認する。
- 1280×900、390×844、844×390で、軍勢・城・荷車が見え、移動/出陣/撤退/帰還/荷下ろし操作が押せることを確認する。

今回の最小完成は、1つの攻略先であっても「地図を挟んだ遠征」「実際の歩行と城攻撃」「持続する制圧地」「手積みして物理搬送で納品する資源供給」が最後まで通り、既存30遭遇へ同じ仕組みを適用できること。全30陣地の通常獲得通し試遊をしていなければ、その完了とは報告しない。
