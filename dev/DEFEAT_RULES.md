# 防衛失敗・再挑戦と拡張の土台

2026-10-28 JST / `20261028-defeat-rules-r1`

## 今回の設計

作った作業場が次の挑戦を支えるゲームにする。失敗の負担は「遠征の区間をやり直す」に置く。設備や資材を失わせて再建を要求すると、主役の手作り自動化を試しにくくなり、弱い編成ほど回復できなくなるため採用しない。主人公HPも追加しない。

| 判定 | 条件・表示 |
| --- | --- |
| 成功 | 箱を1つ以上残し、時間内に全ての襲撃者が撃破または実際の突破で決着。最終波はボス撃破も必須 |
| 箱の損失 | 敵が小屋を突破するたび−1。通常3箱、物資不足の脅威条件では2箱 |
| 箱0 | その場で失敗。残敵の移動・追加出現・撃破報酬を止める |
| 最終ボスの突破 | 箱が残っていても、その場で失敗 |
| 時間切れ | 道に敵が残っていれば失敗。残敵を架空の「突破」に変換しない |

以前は箱0の後も戦闘が続き、締切時の残敵まで突破として処理され、失敗でも8Gを得ていた。今回から理由を `crates / captain / timeout` として保存し、予告・編成画面・結果画面で条件を伝える。内部の `captain` は脅威条件による別ボスにも適用する。

## 失敗からの選択

- **区間を再挑戦**：失敗した区間の先頭、1 / 4 / 7波へ戻る。例：8・9波で失敗したら7波から。今回失敗した波のG報酬は0。
- **引き継ぐ**：資材、地面の実物、自作設備と搬送、農地、研究とスキル、部隊の人数・配置・標的方針、転生コイン、最高戦果。
- 過去の初回クリア受取履歴、精算済みラウンド、ラウンド番号、敵キー、脅威条件を維持。再挑戦だけで初回報酬を復活させない。通常の再クリアGは従来どおり。
- 編成を直す間は襲撃時計だけ停止し、生産は続く。「準備完了」で90秒、急襲条件時はその短縮分を差し引く。未配置部隊は先に置く。
- **戦果を確定して転生**：従来どおり別の選択。最高戦果の増分をコインとして受け取り、戦闘部隊の増員は基本人数に戻る。研究・作業場は維持する。再挑戦との違いを保つ。再挑戦を選んだ後も、次の戦闘開始前なら戦果を確定して転生する選択へ戻れる。

旧セーブの失敗結果も再挑戦の対象。読み込むだけで区間を戻したり、既に受け取った旧8Gを取り上げたりはしない。新しい失敗結果は0Gで保存する。

## 採集を拒否したときの音

置き場上限または落下地点不足で手動採集から実物を出せないとき、低い短い二打を鳴らす。木・石の成功音とは別。自動生産の停止では鳴らさず、700ms以内の連打は間引く。SE設定に従い、この通知ではBGMを下げない。上限に達した地面への採集では、資源や採集仕事量を消費しない既存の処理を維持する。

## 拡張の進め方

今回、`OutpostCore.raidRules` に箱の条件・必須ボス・区間先頭を集約し、`ExpeditionCore.retryQuote` から実際の戻り先をUIにも渡す。文言と復帰処理で別々の境界を計算しない。新しい章や目的を作る際は、この契約と既存9波のデータを一緒に拡張する。可変長章・任意の勝利条件を扱う汎用エンジンはまだ導入していない。

コンテンツを足すなら、既存43ノードの先に単純な攻撃倍率を重ねるより、素材の用途・設備への供給・敵に応じた編成を結ぶのが次の候補。同じ作業場を使って構成を変え、その差が次の3波で分かる拡張にする。追加素材・レシピ・章は今回実装していない。

## 確認

- Nodeテスト309件成功。全9波それぞれの敗北からの戻り先、増員・資材・研究状態・記録・受取履歴・脅威条件・ラウンド番号の保持と再読込を確認。
- `tools/qa_defeat_rules.cjs`：JA/EN/ZH × マウス/CDPタッチの6構成。直前状態を用意した実戦処理で箱0・ボス突破・時間切れを発生させ、実UIで再挑戦→再読込→準備完了。満杯の地面に実ポインター入力を行い、音のデコード・連打制限・SE無効・空き容量回復後の採集を確認。JSエラー0。
- `tools/qa_campaign_recovery.cjs`：同じ6構成で区間待機、未配置ガード、240長コンベアの継ぎ足し、ベルト上の積み込み機、敗北画面と方針変更を回帰確認。
- 機械可読結果は `dev/DEFEAT_RULES_CHECKS.json`。fixtureと既存の新規全編経路は別。今回の新ルールで新規から全編を遊び直した記録ではなく、実機タッチ・音の主観評価・全編成のバランス完成も示さない。以前の通常資材による全編経路は `dev/CAMPAIGN_RECOVERY.md`。
